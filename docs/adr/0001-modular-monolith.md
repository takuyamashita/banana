# 0001 モジュラーモノリスを選ぶ

- 日付: 2026-09-19
- 状態: 採用(2026-09-19 改訂: トランザクションの範囲と切り出しの単位)

## 決定

デプロイ単位は「バックエンド1サービス + Lambda 群 + 静的ホスティング」にまとめ、境界はコード側(crate・集約・proto)で引く。
将来サービスに切り出す単位はコンテキスト(1サービス = 1コンテキスト = 1DB)とする。

## 理由

プロセスを分けると分散システムの運用コストが乗る。まずは境界の明確さだけを先に手に入れる。
コンテキストをまたぐ JOIN・外部キー・トランザクションを禁止しておけば、将来はその境界で別サービスに切り出せる。
集約の間も ID で参照し、他の集約のテーブルへ JOIN・外部キーを張らない。

## 影響

- コンテキストの間の整合は出来事と outbox で取る(同期でまとめて更新しない)。
- 同じコンテキストの集約は、1つのユースケースで1トランザクションにまとめて更新してよい(ガイド 7「判断の記録」)。
  当初は集約をまたぐトランザクションも禁止していたが、1つのユースケースで複数の集約を扱う場面が出ると守れないため改めた。
- レイヤー間・コンテキスト間の依存は scripts/check-deps.sh で CI 検査する。
