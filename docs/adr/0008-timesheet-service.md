# 0008 勤怠(timesheet)を別のサービスとして切り出す

- 日付: 2026-09-20
- 状態: 採用(0001 の「将来の切り出し」を行った)

## 決定

- 勤怠(派遣社員が月の稼働を申告し、管理者が承認する)を、給与とは別のサービスにする。別のプロセス・別の ECS サービス・別のデータベースで、デプロイもサービスごと。
- サービスの間は、同期の呼び出しをせず、出来事だけでつなぐ。
  - 給与 → 勤怠: 派遣社員の登録(`staff.registered`)・案件の登録(`project.created`)。勤怠は写しを持つ。
  - 勤怠 → 給与: 勤務表の承認(`timesheet.approved`、案件ごとの稼働の合計)。給与は「承認された稼働」として持ち、給与明細の明細行に入れる。
- 出来事の形は proto(`acme.<サービス>.events.v1`)で決め、ペイロードは proto の JSON 形で流す。互換は `buf breaking` で守る。給与の中だけで使う出来事(給与明細の確定 → 振込)は Rust の型のまま。
- 配り方: AWS は出す側のサービスごとに SNS FIFO トピック、受け手ごとに SQS FIFO キュー。キューは要る種類(`event_type`)だけを購読のフィルターで受ける。ローカルは ElasticMQ に SNS がないので、relay が受け手のキューへ直接送る(`Publisher` の実装を差し替える)。
- 受け手は server の中の常駐タスクで自分のキューを読む。処理は「届いた内容で置き換える」冪等な形にし、同じ出来事が2回届いても結果が変わらない。知らない種類は読み飛ばし、読めないものは失敗にして再配信と DLQ に任せる。
- データベースは1つの RDS の中にサービスごとに置き、ユーザーも分ける(別のサービスのデータベースは読めない)。データベースとユーザーは各サービスの migrate が作る。
- 入口は ALB を共有し、RPC のパス(`/acme.payroll.v1.*`・`/acme.timesheet.v1.*`)でサービスに振り分ける。ブラウザは同じ API のドメインを使い、画面の transport がサービスごとの宛先に振り分ける(ローカルはポートが違う)。
- コードは `backend/contexts/<コンテキスト>/` と `backend/services/<サービス>/` に分け、コンテキストをまたぐ依存は `scripts/check-deps.sh` で止める。サービスの起動と停止・relay・キューの受け手・設定の読み込み・マイグレーションの流れは共通の crate(`platform-service`・`platform-messaging`・`platform-db`)にまとめる。業務の層の ports(トランザクション・リポジトリのエラー)は共有しない。

## 理由

- 勤怠は給与と別の言葉とモデルを持つ(日ごとの記録と「申告・承認・差し戻し」の流れ。給与は月ごとの明細と金額)。主に使うのも派遣社員で、「本人のデータは本人だけが書ける」権限の型になる。
- サービスを分けたときに要るもの(出来事の約束・配り方・冪等な受け手・サービスごとの DB とユーザー・振り分け・サービスをまたぐトレース)を、サンプルとして一通り示せる。
- 同期の呼び出しにすると、相手が止まっているときに自分も止まり、デプロイの順番も縛られる。出来事でつなげば、相手が止まっていてもキューに溜まり、動き出してから追いつく。
- 同じ RDS に置くのは費用のため。データベースとユーザーを分けておけば、後から RDS を分けるのは接続先の変更だけで済む。

## 捨てた案

- 同じ server の中の別コンテキストにする(0001 のまま): 境界の引き方は示せるが、サービスを分けたときの手間(デプロイ・トレース・配り方)を示せない。
- LocalStack で SNS もローカルに置く: 今の版はアカウントのトークンが要る。relay の送り先の差し替えで足りる。
- 勤怠が給与の API を同期で呼んで派遣社員・案件を確かめる: 給与が止まると勤怠も使えない。写しを持てば独立して動く。

## 影響

- 出来事は「少なくとも1回」届き、届くまで少し時間がかかる(結果整合)。給与で登録した派遣社員が勤怠に届く前に本人が開くと、「まだ届いていない」と伝える。
- 出来事を記録するようになる前の派遣社員・案件は、マイグレーションで outbox に書き足して知らせた。
- relay のロック(MySQL の `GET_LOCK`)は DB サーバー全体で共有されるので、名前をサービスごとにした。
- 設定を上書きする環境変数の接頭辞をサービスごとにした(`PAYROLL__…`・`TIMESHEET__…`)。同じシェル(ローカルの .env)から起動する別のサービスに値が混ざらないようにするため。
- `query!` がコンパイル時に見る DB は crate ごとの `sqlx.toml`(`PAYROLL_DATABASE_URL`・`TIMESHEET_DATABASE_URL`)で決める。
