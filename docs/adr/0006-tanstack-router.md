# 0006 画面の切り替えに TanStack Router を使い、URL・入力の形は生成した型から決める

- 日付: 2026-09-20
- 状態: 採用

## 決定

- 画面は URL で切り替える。TanStack Router のファイルベースのルート(`src/routes/`)を使い、ルートの木(`routeTree.gen.ts`)は Vite のプラグインが生成してコミットする。
- 画面が使うデータは、ルートの `loader`・`beforeLoad` で `ensureQueryData` に先に取らせ、画面は同じメソッドと入力の `useSuspenseQuery` で受け取る(`lib/loaders.ts`)。読み込み中・エラーはルーターの既定の表示にまとめる。
- URL の検索パラメータ(`?staffId=`)とフォームの入力は、protobuf-es が生成した `*Json` 型から形を決め、`fromJson`・`toJson` で読めるかを確かめる(`json_types=true`)。自前の型や検証を書かない。
- Effect を使わない(`useEffect`・`useRef` を置かない)。アプリの初期化(設定の読み込み・ログインからの戻り)は描く前に1回だけ行い、ログインの状態は外部ストアにして `useSyncExternalStore` で読む。
- 画面の部品は、受け取った値を描くだけの関数にする(`XxxView`)。状態と操作は `useXxx` のフックに置き、ページは `<XxxView {...useXxx(props)} />` とつなぐだけにする。
- CloudFront は、拡張子のないパスだけを CloudFront Function で `index.html` に置き換える。見つからないときに HTML を返す設定(custom_error_response)は使わない。

## 理由

- 選んだ派遣社員が URL に残らないと、再読み込み・ブックマーク・ブラウザの「戻る」で画面が初めに戻る。ログイン前に開いた URL にログイン後に戻ることもできない。
- React Router と比べて、パス・検索パラメータ・ローダーの戻り値が型で追え、`validateSearch` で URL を読む場所が1つに決まる。TanStack Query と同じ作りで、取っておいたデータをそのまま渡せる。
- 形を生成した型から取れば、proto を変えたときに画面の型エラーで気づける。検証を `fromJson` に任せれば、数の範囲(int32 など)をサーバーと別に書かない(業務の決まりはサーバーが確かめる)。
- React の「エスケープハッチ」の指針のとおり、Effect は外のシステムとの同期にだけ使うもので、データの取得・初期化・入力から計算できる値には要らない。Effect を置かなければ、StrictMode の2回実行や競合を気にしなくてよい。
- 描くだけの部品は、フックを差し替えずに値だけでテストでき、画面の見た目の変更がデータの取り方に波及しない。
- 404 を HTML で返すと、置き忘れた `config.json` や消えた `assets/` にも 200 が返り、原因が見えなくなる。画面の URL には拡張子がないので、置き換える範囲をそれで分けられる。

## 捨てた案

- React Router(v7): 検索パラメータは文字列のままで、型と検証を画面ごとに書くことになる。ローダーの戻り値に型を付けるにはフレームワークモード(ビルドの仕組みごと入れ替わる)が要る。
- ログインからの戻り先を `beforeLoad` でリダイレクトする: ルーターの最初の読み込みが重なると、先のリダイレクトが後の読み込みに上書きされ、戻り先が失われた(E2E で再現)。ルーターが URL を読む前に `history.replaceState` で戻り先にする。
